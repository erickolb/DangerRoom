More than a list of titles

A collection with the details intact.

01

Find the right edition

Search Metron by series and issue, narrow by series start year, or look up a UPC. Choose the exact cover before adding it. Filter results by series name and format, and hide issues you already own.

02

Track every copy

Keep standard covers, variants, and duplicates together without treating them as interchangeable. Each copy has its own inventory entry. Removing one leaves the others, your ratings, and reading history intact.

03

A cover-specific Want List

Want a variant of an issue you already own? Save that exact cover. Acquiring it removes that want automatically. Reading a comic never claims ownership or clears a wanted cover.

04

Remember the reading

Mark issues read whether or not you own them. Keep an optional dated Reading Log, record rereads separately, and browse your journal by month. Read status and journal entries remain distinct.

05

Make your ratings useful

Rate in half-star steps from 0.5 to 5. Scores are shared across an issue’s copies and covers. Series rating charts show how a run develops, using your saved data without extra Metron requests.

06

Browse what you have

Find saved comics by series, publisher, issue, cover name, UPC, or ISBN. See owned issues across a series’ years and volumes, and open saved artwork at full resolution.

Your instance, your records

Saved locally.
Useful beyond a lookup.

Your collection, wants, ratings, and journal live in SQLite. Saved metadata and cover images are reused when you browse, so revisiting your collection does not call Metron again.

Metron supplies metadata and artwork through read-only requests. Searches are cached and paced; there is no background collection synchronization and DangerRoom does not modify your Metron collection.

Cover originals live in local storage by default, with optional private S3 storage. Back up the database, covers, and configuration together. You control the instance and its retention.

Run your own DangerRoom

One instance. One shared collection.

Use the browser on your computer, phone, or tablet. Add Hardlight for an Android client and its full-screen cover slideshow. You need your own instance, or access from someone who runs one.

What you’ll need

  • A machine with persistent storage and Docker Engine with Compose v2, or Node.js 24+ and pnpm.
  • A Metron account and API token for uncached searches and imports.
  • An HTTPS hostname and reverse proxy for remote access and Hardlight.
  • A backup plan for SQLite, cover files or S3 objects, and private configuration.

Access matters. Browser access has no sign-in by default. Use a trusted network or enable authentication before exposing it publicly. Each Hardlight installation needs a separate device credential.

Start with Docker

For a fresh collection, clone the repository and prepare private configuration:

git clone https://github.com/erickolb/DangerRoom.git
cd DangerRoom
cp .env.example .env
chmod 600 .env
vi .env
sudo docker compose build --pull
sudo docker compose up -d

Set METRON_API_TOKEN and ALLOWED_HOSTS. For public browser access, set REQUIRE_AUTH=true and a strong DANGERROOM_ADMIN_TOKEN. Compose binds port 4340 to loopback; put your HTTPS proxy in front and preserve the original Host header.

Follow the deployment guide for proxy settings, importing data, and verification. Without Docker, prepare configuration, run pnpm install --frozen-lockfile, then pnpm start. The default local address is http://127.0.0.1:4340.
